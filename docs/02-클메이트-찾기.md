# 실행계획 02 — 내 클메이트 찾기

## 1. 개요
크루원이 12문항 클라이밍 성향 테스트를 풀면 16가지 유형 중 하나로 진단되고, 유형 설명과 함께 크루 안에서 나와 잘 맞는 "클메이트"를 추천받는 기능. 45~50명 규모의 크루에서 "이름은 아는데 잘 모르는" 사이를 좁히고, 실제로 같이 암장에 가는 계기를 만드는 것이 목표다.

이 기능은 **크루원 개인 로그인의 첫 번째 이유(트리거)** 역할을 한다. 로그인해야 내 결과를 저장하고 크루 안에서 매칭받을 수 있다. 비로그인으로도 테스트와 결과 공유는 가능하게 해서 유입 경로로 쓴다.

## 2. 요구사항
| # | 요구사항 | 비고 |
|---|---|---|
| R1 | 12문항 A/B 선택형 테스트(축당 3문항), 이전 문항으로 돌아가 수정 가능 | 4축 번갈아 출제, 선택지 좌우 순서 섞기 |
| R2 | 결과: 유형 별칭, 축 조합 표기(예: 교류 · 역동 · 집중 · 분석형), 캐치프레이즈, 설명, 강점 3개, 성장 팁 | 영문 약자는 쓰지 않는다 |
| R3 | 축별 응답 막대 + 2:1로 갈린 축은 "가끔은 ○○형 모습도 보여요" 표시 | 3:0 확신형 / 2:1 경계형 |
| R4 | 궁합 유형 3종 표시: 최고의 클메이트 / 잘 맞는 클메이트 / 같이 가면 새로운 경험 | **점수는 계산하되 화면에 표시하지 않는다** |
| R5 | 결과 공유: 공유 URL + OG 이미지, 공유받은 사람은 "나도 해보기" | 암장 랜덤뽑기 공유 구조 재사용 |
| R6 | 크루원 개인 로그인 후 결과 저장, 재검사 가능(최신 결과로 갱신) | 로그인 방식은 6장 결정 필요 |
| R7 | 크루 안 클메이트 추천: 결과를 저장한 크루원 중 궁합 순으로 추천 | 단계 3 |
| R8 | 프로필 공개 범위 본인 선택(크루 공개 / 비공개) | 비공개면 추천 대상에서 제외 |

## 3. 화면/라우트
| 경로 | 설명 |
|---|---|
| `/climbmate` | 소개 + 테스트 시작 (R1) |
| `/climbmate/test` | 12문항 진행 화면 (R1) |
| `/climbmate/result/[code]` | 결과 화면(공유 가능, 읽기 전용) + "나도 해보기" (R2~R5) |
| `/climbmate/result/[code]/opengraph-image` | 결과 카드 OG 이미지 |
| `/climbmate/me` | 로그인한 내 결과 + 크루 클메이트 추천 (R6~R8) |

- 결과 식별자 `code`: 축 결과 4자리 + 축별 응답 수를 URL에 인코딩한다(예: `0101-2130`). DB 없이 결과 페이지를 재현할 수 있다. 랜덤뽑기 A안과 같은 방식이다.

## 4. 유형 체계

### 4.1 4축
| 축 | 왼쪽 | 오른쪽 | 측정 대상 |
|---|---|---|---|
| 교류 성향 | 교류형 — 사람이 있어야 힘이 난다 | 독립형 — 내 트라이가 더 중요하다 | 등반 중 에너지를 어디서 얻는가 |
| 움직임 방식 | 역동형 — 닿을 것 같으면 던진다 | 제어형 — 뜯어서 간다 | 다이나믹 vs 스태틱 선호 |
| 세션 운영 | 집중형 — 될 때까지 그것만 | 탐색형 — 찍먹부터 | 한 문제 파기 vs 넓게 훑기 |
| 문제 접근 | 분석형 — 벽이랑 먼저 회의 | 실행형 — 일단 붙고 생각 | 붙기 전에 읽는가, 붙으면서 푸는가 |

| 9 | 교류 | 쉬는 시간에 나는 주로 | 다음 루트를 보면서 혼자 이미지 트레이닝 (독립) | 매트에 앉아 수다 떨며 남의 트라이 응원 (교류) |

| 11 | 세션 | 같은 문제를 5트째 실패했다. | 6트, 7트… 될 때까지 (집중) | 일단 다른 거 하고 나중에 다시 (탐색) |
| 12 | 접근 | 막히는 구간이 생기면 | 그 구간만 계속 붙어서 몸으로 익힌다 (실행) | 내려와서 벽 앞에서 손으로 허공 시뮬레이션 (분석) |

화면에는 괄호 속 성향을 표시하지 않는다.

### 4.3 판정
- 축마다 3문항 중 2개 이상 고른 쪽으로 결정한다(동점 없음).
- 3:0은 확신형, 2:1은 경계형으로 저장한다. 경계형 축은 결과 화면에 "가끔은 ○○형 모습도 보여요"로 반대 성향을 표시한다.

## 5. 궁합 로직

### 5.1 점수 (0~8점, 화면 비노출)
| 축 | 기준 | 가중치 | 이유 |
|---|---|---|---|
| 세션 운영 | 같으면 + | 3 | 한 문제 파기 vs 넓게 훑기가 다르면 같이 다니기 어렵다 |
| 교류 성향 | 같으면 + | 2 | 응원·수다를 원하는 사람과 혼자 집중하고 싶은 사람은 서로 피곤하다 |
| 문제 접근 | 다르면 + | 2 | 분석형이 베타를 짜고 실행형이 바로 테스트하는 보완 관계 |
| 움직임 방식 | 다르면 + | 1 | 서로 못하는 무브를 보고 배운다 |

- 유형 단위: 나를 뺀 15유형을 점수순으로 정렬해 1위를 "최고의 클메이트", 2위를 "잘 맞는 클메이트", 최하위를 "같이 가면 새로운 경험"으로 표시한다. 각 순위는 유일하게 정해진다(8점 / 7점 / 0점).
- 최고 궁합은 항상 서로를 가리킨다(아래 8쌍).
- "같이 가면 새로운 경험"은 최악 궁합이지만 부정적으로 표현하지 않는다.

### 5.2 최고 궁합 8쌍 문구
| 짝꿍 | 문구 |
|---|---|
| 작전회의 대장 × 끈기 응원단장 | 한 명은 작전을 짜고 한 명은 끝까지 버팁니다. 둘이면 2주짜리 프로젝트도 끝나요. |
| 불꽃 돌격대장 × 베타 코치 | 던지는 사람과 읽는 사람. 코치가 베타를 주면 돌격대장이 바로 증명합니다. |
| 암장 탐험대장 × 분위기 메이커 | 새 세팅 날 제일 먼저 도착해서 제일 많이 웃고 가는 조합. |
| 파티 다이노 × 친절한 루트 해설가 | 해설가가 길을 보여주면 다이노가 그 길을 날아갑니다. |
| 고독한 저격수 × 묵묵한 장인 | 말은 없어도 서로의 트라이를 존중하는, 조용하지만 단단한 조합. |
| 무한 트라이 머신 × 벽 위의 체스기사 | 체스기사가 수를 읽고 트라이 머신이 그 수를 몸으로 확인합니다. |
| 조용한 사냥꾼 × 마이페이스 산책러 | 각자 돌다가 같은 문제 앞에서 마주치는, 부담 없는 동행. |
| 자유로운 영혼 × 고요한 관찰자 | 관찰자는 자유로운 영혼의 움직임에서 영감을 얻고, 그 반대도 마찬가지. |

### 5.3 크루원 단위 추천 (단계 3)
- 50명을 16유형으로 나누면 유형당 평균 3명이라 최고 궁합 유형이 크루에 없을 수 있다. 그래서 실제 추천은 **결과를 저장한 크루원 전체를 사람 단위 점수로 정렬**한다.
- 경계형(2:1) 축은 가중치를 절반만 반영해서 같은 유형끼리도 순위가 갈리게 한다.
- 동점이면 최근 결과 저장 순으로 정렬하고, 매주 월요일 로테이션 시드를 바꿔 같은 사람만 반복되지 않게 한다.

## 6. 데이터·인증

### 6.1 현재 상태
- 로그인은 크루 공용 뷰어 PIN(`settings.viewer_pin_hash`)과 관리자 비밀번호 두 가지다. JWT 세션(`src/lib/session.ts`, `src/proxy.ts`)에 **개인 식별 정보가 없다.**
- 크루원은 `members` 테이블에 이름·가입일·인스타그램 ID로 관리된다.

### 6.2 개인 로그인 (결정 필요)
| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A안 (권장) | 이름 선택(`MemberSelect`) + 개인 4자리 PIN(`PinPad` 재사용). 첫 로그인 시 PIN 설정, 분실 시 관리자가 초기화 | 기존 UI·세션 구조 재사용, 외부 연동 없음 | PIN 분실 대응을 운영진이 해야 함 |
| B안 | 카카오 로그인 후 `members`와 1회 연결 | 가입·로그인 허들이 가장 낮음 | 카카오 앱 등록·심사, 계정 연결 화면 필요 |

- A안이면 `members`에 `pin_hash text`, `pin_set_at timestamptz`를 추가하고, 세션 JWT 페이로드에 `mid`(member id)를 넣는다. 기존 공용 PIN 세션은 그대로 유지한다(조회 화면용).
- 로그인 시도 제한은 기존 `login_attempts`에 scope `'member'`를 추가해서 재사용한다.

### 6.3 테이블
```sql
-- 성향 테스트 결과 (크루원당 최신 1건)
create table climb_profiles (
  member_id   bigint primary key references members(id),
  axes        smallint[] not null,  -- 축별 오른쪽 성향 선택 수 [0~3] x4 (교류,움직임,세션,접근)
  type_key    text not null,        -- 예: '교역집분'
  visibility  text not null default 'crew' check (visibility in ('crew','private')),
  answers     smallint[] not null,  -- 12문항 원응답 (문항 개편 시 재계산용)
  updated_at  timestamptz not null default now()
);
```
- 단계 4(같이 가요)에서 `mate_proposals(id, from_member, to_member, gym_id, proposed_for date, status, created_at)`를 추가한다.

### 6.4 콘텐츠 데이터
- 문항, 16유형 설명, 8쌍 문구, 가중치는 `src/lib/climbmate.ts`에 정적 상수로 둔다(`gyms.ts`와 같은 방식). 판정·점수 함수도 같은 파일에 순수 함수로 둔다.

## 7. 구현 단계

### 단계 1 — 테스트·결과 (비로그인)
1. `src/lib/climbmate.ts`: 문항, 유형, 궁합 문구, `judge(answers)`, `score(a, b)`, `rankTypes(me)` 작성
2. `/climbmate`, `/climbmate/test`: 한 문항씩 진행, 진행 바, 이전 문항 이동
3. `/climbmate/result/[code]`: 유형 설명, 축별 막대, 경계형 문구, 궁합 3종(점수 비노출)
4. 공유: `ShareBar` 재사용, `opengraph-image`로 결과 카드 생성, "나도 해보기" 버튼
5. `proxy.ts` 공개 경로에 `/climbmate` 추가, 메인 메뉴(`MenuCard`)에 진입점 추가

### 단계 2 — 개인 로그인
1. 6.2에서 로그인 방식 확정
2. 마이그레이션: `members.pin_hash`, `login_attempts` scope 확장, `climb_profiles`
3. `/api/auth/member` 로그인·PIN 설정 API, 세션에 `mid` 추가
4. 관리자 화면에 크루원별 PIN 초기화 버튼 추가
5. 결과 화면에 "로그인하고 결과 저장하기" 버튼(로그인 후 결과 자동 저장)

### 단계 3 — 크루 클메이트 추천
1. `/climbmate/me`: 내 결과 + 공개 범위 토글 + 크루원 추천 목록
2. 추천 카드: 이름, 유형 별칭, 관계 라벨(최고의 / 잘 맞는 / 새로운 경험), 최고 궁합이면 8쌍 문구
3. 크루 성향 분포(유형별 인원) 요약 화면
4. 결과 저장 인원이 10명 미만이면 "아직 크루원이 모이는 중" 안내와 유형 단위 결과만 표시

### 단계 4 — 같이 가요 (선택)
1. 추천 카드에서 "같이 가요" 제안(암장·날짜 선택), 상대는 수락/다음에로 응답
2. 거절은 상대에게 "다음에 가요"로만 표시
3. 수락된 동행 기록은 이후 포인트·뱃지 기능과 연결

## 8. 리스크·확인 필요
- Next.js 버전이 일반 지식과 다르므로 구현 전 `AGENTS.md`와 `node_modules/next/dist/docs` 확인
- 개인 로그인 방식(A안/B안) 결정 전에는 단계 2 이후를 진행하지 않는다
- 초기 참여자가 적으면 추천이 빈약하다. 오픈 전에 운영진이 먼저 테스트하고 단톡방에 결과 카드를 공유해서 참여를 끈다
- 성별·연령 기반 매칭은 하지 않는다. 소개팅처럼 느껴지면 모임 분위기를 해친다
- 연락처는 노출하지 않는다. 연결은 앱 안 제안 또는 기존 인스타그램 ID(본인 동의 시)로만 한다
- 문항은 크루원 5~10명 파일럿 후 한쪽으로 80% 이상 쏠리는 문항을 교체한다. `answers` 원응답을 저장해 두면 개편 후 재계산할 수 있다
- 다른 서비스의 축 구성을 참고했으므로 유형명·문구·디자인은 크루 고유 버전을 유지한다

## 9. 완료 기준
- 단계 1: 비로그인으로 테스트 → 결과(설명·막대·궁합 3종, 점수 비노출) → 공유 URL과 OG 이미지 → "나도 해보기"까지 모바일/데스크톱에서 동작
- 단계 2: 크루원이 개인 PIN으로 로그인해 결과를 저장하고, 재검사하면 최신 결과로 갱신된다
- 단계 3: 공개 설정한 크루원 사이에서 사람 단위 궁합 순 추천이 표시되고, 비공개 크루원은 추천에 나오지 않는다
